# NLP project

`src/` contains training code, `scripts/` run scripts, `plotting/` notebooks and plotting tools, `docs/` background documentation, and `data/` the dataset. Results stay in `results/`.

Run all commands from the project folder. Use Python 3.9–3.12.

1. **Set up the environment** (CPU):

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   python -m pip install jupyterlab ipywidgets
   ```

   In a new terminal, activate the environment again with `source .venv/bin/activate`.

2. **Run training:**

   ```bash
   bash scripts/nlp_project_run.sh
   ```

   The script uses the included `data/omniglot_resnet18_randomized_order_s0.h5` dataset. Edit `MAIN_RUN_ITERS` in the script for a shorter run (default: 1,000,000 sequences, or 31,250 batches).

   Terminal output (including errors) is also saved to `results/<timestamp>_nlp_project_run_<pid>.log` while training runs.

3. **Find the outputs:** each run creates `results/<timestamp>_omniglot50_rl5/`, containing:

   - `config.json` — run settings.
   - `log.h5` — training and evaluation metrics.
   - `checkpoints/*.eqx` — saved model checkpoints.

4. **Plot the results:**

   ```bash
   mkdir -p results/figures
   jupyter lab plotting/ih_paper_plots.ipynb
   ```

   The notebook setup cell locates the project root automatically. Use the `.venv` Python kernel and keep `base_folder = './results'`. In the notebook, replace the exact path segment `/omniglot50_rl5/` with `/<timestamp>_omniglot50_rl5/` for your chosen run.

   Run the opening setup cells, then **Figure 3a** for loss curves. Continue through **Figure 3b** and **Figure 4a** for attention and ablation plots. Stop before **Figure 4b**: that section and later plots need additional training runs that this script does not produce.

   Plots appear inline and are saved as PDFs in `results/figures/` (including `figure_3a.pdf`, `figure_3b.pdf`, and `figure_4a.pdf`). Replotting replaces PDFs with the same names.

## Model collapse: base and extended variants

The run script takes these settings as environment variables:

- `MODEL_VARIANT=base` (default) predicts the query's value. `MODEL_VARIANT=extended` also predicts the next symbol and that symbol's value.
- `NEXT_SYMBOL_SOURCE` (extended only): `context` (default) picks the next symbol from the symbols already in context, so its value can be copied in-context. `global` draws it from the training class distribution, so it may be a symbol not in context, which gets a fresh value.
- `GENERATIONS` and `GEN_DATASET_SIZE`: each generation trains on a fixed pool of `GEN_DATASET_SIZE` sequences. Generation 0's pool is real data. Before each later generation, `GEN_REPLACE_FRAC` (default 0.1) of the pool is regenerated by the previous generation's model, so the pool size stays the same.

For example, three generations of the extended model:

```bash
MODEL_VARIANT=extended GENERATIONS=3 GEN_DATASET_SIZE=20000 bash scripts/nlp_project_run.sh
```

Generated tokens are sampled from softmax(logits / T), with T = 1 by default. To change this, pass `--gen_sampling argmax` or `--gen_temperature` to `src.main`. By default each generation trains from a fresh initialisation; `--gen_init continue` keeps training the previous model instead.

With a pool, each generation writes `gen_<g>/log.h5`, `gen_<g>/checkpoints/` and `gen_<g>/pool_meta.npz` (labels, symbols and the generation that produced each item). `generations.h5` holds one row per generation of pool metrics: the share of real data, query label error, and for the extended model the next symbol's entropy, KL to generation 0, number of distinct symbols, top-10 and tail mass, and how often it falls outside its context.

See [model_collapse.md](docs/model_collapse.md) for the full description of the extension, its outputs, and its metrics, and [Paper_README.md](docs/Paper_README.md) for the original paper documentation.
